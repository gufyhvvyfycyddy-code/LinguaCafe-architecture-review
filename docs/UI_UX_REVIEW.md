# UI / UX Review — Current Direction

状态：基于当前产品计划、代码结构和历史验收的审查框架。当前 baseline 的真实浏览器复验仍由 Issue #4 持有。

## 目标体验

普通用户每天打开 LinguaCafe 应该先回答一个问题：

“我今天要做什么？”

当前产品方向：
- 首页：打卡、连续学习、今日阅读、今日待复习、继续学习；
- 阅读；
- 复习；
- 生词；
- 我的。

高级 Browser、Card Info、复杂统计、FSRS 参数、备份恢复工程界面不应该占据普通用户的一级注意力。

## 与墨墨 / MaiMemo 的关系

墨墨官方强调：
- 内容简洁；
- 复习有的放矢；
- 数据一目了然；
- 日常任务操作少。

参考：
https://www.maimemo.com/
https://memodocs.maimemo.com/docs/memo/

LinguaCafe 借鉴信息层级和每日任务感，不复制其界面、词库结构或付费模型。

## 当前 UX 风险

### 1. 旧产品历史容易混进当前界面

源项目长期包含多语言、Jellyfin、DeepL、Anki API 等历史能力。当前 LinguaCafe 已收窄到英文阅读 + WordSense + FSRS。

审查重点：
- 普通用户还能否看到已经离开主线的入口；
- 设置页是否仍被历史能力挤占；
- 空功能/未配置功能是否表现成错误。

### 2. 工程信息过多

风险区域：
- FSRS 内部字段；
- Browser / Card Info；
- 手动调度；
- 复杂统计；
- 调试/服务器状态；
- 高级导入导出。

这些能力可以保留，但应该进入“高级”或管理入口。

### 3. 首页必须能真正继续学习

首页不能只是统计看板。

必须清楚提供：
- 当前最重要的一个 CTA；
- 最近未完成阅读；
- 今日需要复习数量；
- 今日已完成情况；
- 下一步动作。

### 4. 阅读页不能让查词打断阅读

社区中反复出现“做卡会打断阅读”的抱怨。

参考：
https://www.reddit.com/r/Anki/comments/d8nsjs/
https://www.reddit.com/r/languagelearning/comments/1d4mx2j/

因此审查阅读页时重点看：
- 点词后到看到解释需要几步；
- 确认词义是否迫使用户离开正文；
- 词义建议和正式加入学习是否混淆；
- 用户回到原句是否自然；
- 手机长按/拖选词组是否稳定。

### 5. 复习页要把学习内容放在工程信息前面

顺序建议：
1. 问题/原文语境；
2. 用户回想；
3. Show Answer；
4. 中文/英文释义和必要来源；
5. Again / Hard / Good / Easy；
6. 更多信息进入次级入口。

### 6. 错误状态要像产品，不像后台

需要统一检查：
- 词典无结果；
- tokenizer 不可用；
- AI JSON 错误；
- 网络离线；
- 同步冲突；
- 可选集成未配置；
- 登录失效。

用户需要知道“现在发生了什么、还能做什么”，而不是看到 500、stack trace 或内部名词。

### 7. 移动端需要独立验收

Web responsive 不能替代原生移动验收。

Android/iOS 分别检查：
- 返回；
- 前进；
- 底部导航；
- safe area；
- 键盘；
- Bottom Sheet；
- 长按；
- 断网；
- App 杀进程后恢复；
- 离线操作同步。

## 视觉美化优先级

视觉优化按以下顺序：
1. 信息层级；
2. 间距与可读性；
3. 主 CTA；
4. 状态反馈；
5. 窄屏/触摸；
6. 颜色和图标一致性；
7. 动效。

不要先换颜色/阴影，再保留混乱的信息结构。
